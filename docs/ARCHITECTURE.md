# Architecture

Ferry is a Cargo workspace with three crates:

* **`ferry`** (repository root) – the library: protocol, transfers, discovery, pairing,
  configuration. It has no user interface and no terminal or GUI dependencies.
* **`ferry-cli`** (`cli/`) – the `ferry` binary: command line, terminal UI (`ratatui`), background
  daemon and `ferry doctor`.
* **`ferry-gui`** (`src-tauri/`) – the Tauri v2 application for Linux, Windows and Android;
  `src-tauri/ui/` is the frontend (plain HTML, CSS and JavaScript modules, no build step).

Both interfaces use only the library's public API.

```text
 ferry-cli: CLI, TUI, daemon (cli/src)          ferry-gui (src-tauri)
                     │                                │
                     └──── implement TransferHandler ─┘
                                     │
 ferry library ──────────────────────▼──────────────────────────────────────
   transfer/   service (accept loop, events), sender, receiver, path security
   pairing.rs  commit-reveal pairing code
   discovery/  signed UDP announcements on the local network
   node/       iroh endpoint, persistent identity, TICKET
   protocol/   messages + length-prefixed postcard codec (no I/O)
   config/     config.toml, trusted devices, paths      i18n.rs  languages
   error.rs    error classification for callers          size.rs, system.rs  helpers
```

## Layers

| Module | Responsibility |
|--------|----------------|
| `protocol` | Wire types and framing. Pure data; every received value has a `validate`. |
| `node` | `NodeEngine` wraps an iroh `Endpoint` (local or internet [`NetworkMode`](../src/node/engine.rs)), loads the device key, builds TICKETs. |
| `transfer::sender` / `receiver` | One file over one control stream: offer, decision, chunk streams, verification, resume. |
| `transfer::security` | Turns names and folders from peers into safe paths inside the download folder. |
| `transfer::service` | The accept loop shared by all interfaces (`serve`), outgoing `send_files` / `pull_shared` / `send_text`, events, cancellation and rate limits. |
| `discovery` | Announces this device and keeps the list of nearby devices; hidden mode. |
| `pairing` | Both sides of the pairing exchange and the verification code. |
| `config` | `config.toml` (trusted devices, download folder, name, language, network mode, privacy). |

## Interfaces

Every interface implements the `TransferHandler` trait from `transfer::service`:

* `decide` / `decide_batch` – accept or decline incoming files,
* `confirm_pair` – show the pairing code and ask,
* `receive_text` – ask and copy to the clipboard,
* `on_event` – render `TransferEvent`s (progress, completion, failure, cancellation).

`serve` runs one task per incoming connection; the handler is shared. The interfaces differ
only in how they ask the user:

| Interface | Location | Asking |
|-----------|----------|--------|
| CLI | `cli/src/cli/` | one-shot commands; progress bars with `indicatif` |
| TUI | `cli/src/tui/` | `ratatui`; questions are queued as popups |
| Daemon | `cli/src/daemon/` | terminal prompts, or Auto-Accept only without a terminal |
| GUI | `src-tauri/src/node.rs` | Tauri events to the web view, system notifications |

The GUI talks to the frontend through Tauri commands (`src-tauri/src/commands.rs`) and events
(`transfer`, `incoming-offer`, `pair-request`, `pairing-code`, `pair-result`, `nearby`, …).

## Android

`src-tauri/gen/android/` is the Android project generated by Tauri and extended by hand
(package `io.github.vp859.ferry`):

* `MainActivity.kt` – share target (`ACTION_SEND` / `SEND_MULTIPLE`), runtime permissions,
* `ShareIntake.kt` – copies shared `content://` files into the app cache,
* `FerryService.kt` – foreground service with a notification and a multicast lock, so the node
  keeps running in the background; wake and Wi-Fi locks while transfers run,
* `PowerHelper.kt` – what limits the app in the background (battery optimization, battery
  saver, background restriction, data saver) and the way to the system app settings,
* `src-tauri/src/platform.rs` – Android-specific Rust: storage folders, media scanning and the
  calls into the Kotlin classes above via JNI.

### Background limits

* The service is of type `connectedDevice` (exchanging data with other devices over the network),
  which has no daily time limit; `dataSync` is a fallback for phones that refuse it. Android 15+
  stops `dataSync` after 6 hours a day: Ferry then stops the service cleanly and posts a
  notification that opens the app, instead of being killed.
* While at least one transfer runs (`AppState::track_transfer`), a partial wake lock and a
  Wi-Fi lock keep the phone from sleeping or slowing Wi-Fi down with the screen off.
* Doze and battery optimization can still pause the network for minutes. A sender then
  reconnects up to three times (2 s, 5 s, 15 s) and the receiver resumes the partial file without
  asking again; *Settings → Background* in the app shows the limits and opens the system settings
  where battery use can be set to unrestricted.
* Manual checks (Doze, standby buckets, battery saver) are listed in [TESTING.md](TESTING.md).

Logs: `adb logcat -s FerryCore FerryService FerryShare FerryPower`.

## Data flow of a file

1. The sender walks folders (`expand_paths`), announces several files as a batch and hashes each
   file (BLAKE3) right before sending it.
2. The receiver validates the offer, asks the handler (or uses the batch approval), and replies
   with the first chunk it still needs.
3. Chunks (1–8 MiB, growing with the file) travel on separate unidirectional streams, about
   8 MiB in flight; the receiver writes them in
   order to `<name>.<hash>.part`, hashing as it goes.
4. After the last chunk the whole-file hash is compared, the `.part` file is renamed to a free
   name, and `Verified` is sent back.

## Design decisions

* **No mDNS, no Bluetooth** – plain UDP broadcast/multicast works on every OS without extra
  services or permissions (except Android 17's local network permission).
* **No servers by default** – iroh runs with relays and DNS lookup disabled; internet mode is an
  explicit opt-in.
* **No frontend build step** – the GUI is plain HTML, CSS and ES modules (`src-tauri/ui/js/`:
  `app.js` with the features, `dom.js`, `i18n.js` with `locales/`, `tauri.js` as the bridge to the
  native side). Scripts are separate files, so the Content-Security-Policy forbids inline
  scripts. CI checks syntax and translation keys (`scripts/check-frontend.mjs`), lints with Biome
  and runs Playwright tests against a mocked Tauri API (`tests/gui/`).
* **Errors** – the library returns `anyhow` errors with a localized context chain;
  `ferry::error::kind` classifies them (cancelled, connection, timeout, protocol, integrity,
  unsafe path, disk full, …) through typed errors in the chain, so callers never parse messages.

## Former name

Ferry was called "RQS P2P Quick Share". What remains of that name is on purpose:

* `~/.config/rqs` (and the same folder on Windows) is moved to `~/.config/ferry` on the first
  start (`config::paths::migrate_legacy_dir`), so devices keep their identity and pairings.
* The old Android app `com.rqs.quickshare` is a different package; it is not updated and has to
  be uninstalled by hand.

Everything else – crates, binaries, protocol identifiers, Android classes – uses the new name.
* **Shared accept loop** – all interfaces behave the same because the protocol logic lives in
  `serve`, not in the interfaces.
